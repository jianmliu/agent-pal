# Agent-PAL-Bench: Evaluating Long-Horizon Decision-Making in a Chinese Role-Playing Game Through Text-Based Interaction

> Working paper, version 0.3, evidence review dated 20 October 2026. Implemented mechanisms, development audits, exploratory agent runs, and proposed experiments are distinguished throughout. This is not a frozen benchmark release or a capability-matched model leaderboard. The English Markdown is the content source for the standalone English LaTeX version; the Chinese manuscript follows the same claims and results.

## Abstract

Persistent role-playing games combine dialogue comprehension, spatial exploration, cross-scene causality, and resource management. We introduce **Agent-PAL-Bench**, a text-based agent benchmark built on a headless execution environment for *The Legend of Sword and Fairy*. Agents issue structured tool calls and receive textual game-state feedback; gameplay video is not an agent input. Beyond the default `assist` (L1) layer that exposes high-level semantic tools, the environment implements a `--pure` mode that exposes only low-level protocol primitives (L0) and in-session dynamic self-coding (`run_code` and `module_reload`). The reviewed working catalog contains 23 tasks and 67 planned task–seed episodes. Tasks specify starting states, state-based goals, budgets, information conditions, and reference trajectories. A current-build audit reaches the goal on 59/67 reference trajectories, exposing release-blocking failures rather than model errors. A separate, frozen two-task audit repairs missing appearance cues and premature goal detection, calibrates action budgets, and evaluates three built-in cloud agents and one externally scaffolded agent on game seed 42. All eight evaluation episodes exhaust their action budgets without success and pass trajectory replay; calibration and reference successes are reported separately. In addition, we validate the `--pure` mode end-to-end under deterministic lockstep (`--seed 1`) across three external agents (Argon, GPT-6.1-Sol, and Claude Opus 5.5): operating strictly from `SMSG_*` state packets and `CMSG_*` primitives, the three agents independently synthesize 731-line, 135-line, and 1,427-line runtime libraries in session scope (spanning bytecode-graph BFS pathfinders, connected-component dungeon planners, resistance-adaptive combat engines, and menu state machines), each completing all 11 chapters from a new game to the final boss (`Baiyue`, 32,760 HP) across sequential save checkpoints (`Slots 1–99`). The findings identify observation fidelity, context retention, resource preparation, tool-abstraction layer, and self-coded architectural divergence as measurement concerns. They do not establish a regional model advantage, a causal success-rate gain from the repairs, or a measure of planning alone.

**Keywords:** language agents; game benchmarks; Chinese RPGs; long-horizon planning; text interaction; tool self-coding; reproducibility

## 1. Introduction

Knowing where to find the Water Spirit Orb is different from finding the relevant characters, retaining a necessary item, crossing scenes, and completing an exchange within an action budget. Knowing that a final boss requires damage is different from conserving resources through prerequisite fights and adapting when a healer is silenced or incapacitated. A persistent game lets us examine how an agent turns information into consequential actions.

We use a Chinese fantasy RPG because dialogue, character relationships, implicit prerequisites, map mechanisms, equipment, and consumables interact in one authored world. Whether familiarity with Chinese game language and culture improves situated decisions is an open research question. Model developer location does not measure that familiarity. Scale, pretraining, reasoning budget, tools, information access, and agent scaffolding must be controlled before attributing differences to cultural knowledge.

This paper contributes: (1) a working collection of replayable RPG segments, including same-goal starting-state variants, causal item chains, and synthetic combat configurations; (2) a protocol based on fixed saves, game seeds, virtual time, state predicates, and action replay; (3) explicit tool and hint conditions, distinguishing the built-in white-box high-level tool layer (`assist` L1) from the low-level protocol and dynamic self-coding layer (`--pure` L0 + `run_code`/`module_reload`); and (4) a two-task development audit showing how missing observations, an early-success predicate, and context policy complicate failure attribution, complemented by an end-to-end `--pure` self-coding playthrough from new game to final credits that validates L0 protocol completeness. The implemented environment, development validations, and the proposed inferential study have different evidential status. The latter remains unfinished.

## 2. Related Work

[AgentBench](https://arxiv.org/abs/2308.03688) evaluates agents across interactive environments. [TextWorld](https://arxiv.org/abs/1806.11532) supports state tracking and controlled generation of text games; our tasks use an existing authored RPG. [Jericho](https://arxiv.org/abs/1909.05398) studies human-authored interactive fiction. Agent-PAL-Bench shares its exploration demands and also exposes party, equipment, consumable, and combat systems. [ScienceWorld](https://arxiv.org/abs/2203.07540) distinguishes factual recall from applying knowledge in an interactive environment. [ALFWorld](https://arxiv.org/abs/2010.03768) connects text and embodied environments, highlighting the distinction between text-mediated decisions and visual understanding. [GameBench](https://arxiv.org/abs/2406.06613) and [BALROG](https://arxiv.org/abs/2411.13543) provide broader game-based comparisons.

RPG agency itself is not new: the [PokeAgent Challenge](https://arxiv.org/abs/2603.15563) includes competitive battling and RPG speedrunning, and [PokeGym](https://arxiv.org/abs/2604.08340) evaluates visually driven long-horizon tasks and adaptation. Our scope is a Chinese-language authored RPG with inspectable task predicates and structured text interaction. We make no priority claim for RPG planning, persistent worlds, or game-agent evaluation. Our reported scores cannot be compared directly to visual or differently scaffolded benchmarks.

## 3. Environment and Tasks

### 3.1 Interaction and replay

Each episode runs an isolated game process from a new game, a classic RPG save, or a fixed benchmark save slot, with a game random seed. Tools include `observe`, `map`, movement, interaction, dialogue advance, menu choices, items, spells, and battle actions. Game simulation is paused between calls; advancing actions move virtual time, whereas observation and reference-material queries do not. Model inference latency therefore does not itself advance the game. Wall-time limits remain a separate harness constraint. Saves and map memory are isolated between episodes. Video is for human inspection, not the B/C-tier agent or grader. The reviewed task catalog opens no visual A-tier tasks.

A task defines its start, goal predicates, optional milestones and failure conditions, budgets, and tools. The grader reads state such as scene visits, inventory, event-object state, battle outcomes, and dialogue history. `check` replays references. `verify` replays logged actions and compares per-step grading state and terminal game outcomes. It does not rerun model inference or independently validate token accounting, cost, or model-side stopping causes. Standard replay is not a proof that all observation text was complete or accurate; the appearance audit adds native observation checks and selected response-equivalence checks. A successful reference is a feasibility witness for that version and seed, not an optimal policy or a model result.

The current general-task runner records a Git revision label, task versions, seeds, prompt version, and logs; battle-scored runs additionally record runtime/asset and task/save fingerprints. General-task runs do not automatically receive all those hashes. The frozen appearance experiment therefore supplies separate manifests. A `-dirty` label alone cannot identify the exact executable, assets, or task contents.

### 3.2 Reviewed working catalog

The reviewed main working tree at base `3e316b4c`, including uncommitted development tasks, contains **23 tasks and 67 planned task–seed episodes**: 23 support B and 18 also support C; 11 start from classic saves, eight from fixed benchmark saves, and four from a new game. These are development counts, not a fully validated release or 67 independent stories.

| Capability family | Example | Representative criterion |
|---|---|---|
| Narrative progress | Serving guests; Yangzhou events | Required story or dialogue event occurs |
| Spatial mechanisms | Fairy Island statues; tower gate | Scene or event state changes |
| Cross-scene item chains | Handkerchief to Water Spirit Orb; rain ritual | Required item or causal goal is reached |
| Survival and tactics | One-life island; Baiyue variants | Victory with task-specific restrictions |
| Resource allocation | Palace prerequisite-fight reserve pilot | Story/battle predicates plus retained items and cash |

New-game, island, and corridor starts share the same first-meeting goal and ordinary failure rules, but have different starts and budgets. They do not isolate horizon at equal budget. The one-life variants add restrictions and are separate conditions. The palace reserve pilot has only seed 42; its reference has 35 calls and it is not a continuous guard–tree demon–Baiyue evaluation. Four Baiyue single-battle variants change resources or character capabilities and are synthetic configurations. They do not estimate the effect of natural leveling.

### 3.3 Information and context conditions

B provides structured text tools; C adds walkthrough and atlas access. Independently, `standard` suppresses some script-derived purpose/requirement hints that `full` exposes. Standard is not a guarantee of pixel-equivalent information: structured coordinates, IDs, navigation categories, and state summaries remain abstractions. Item-effect information may still be present under standard. `observe(full=true)` requests expanded observation; it is distinct from the environment's `hints=full` setting.

The built-in loop retains the full text of only the latest **six tool results**, replacing older results with placeholders while preserving assistant text and call records. An earlier clue may disappear unless the agent records or reacquires it. Claude CLI manages its own context. Built-in usage is checked against the token budget after each model turn; external CLI usage is merged only at episode end, so the task token cap is not enforced incrementally there. These differences require separate reporting. Translating only the brief does not remove Chinese game dialogue; an English-only observation condition and comprehensive name masking are not implemented.

### 3.4 Assist (L1) versus pure (L0 + dynamic self-coding) execution modes

To separate the contribution of pre-authored high-level tool scaffolding from an agent's ability to synthesize its own policies and abstractions over raw protocol primitives, the environment implements two distinct execution layers: the default `assist` (L1) mode and the `--pure` (L0 + dynamic self-coding) mode.

| Dimension | `assist` mode (built-in L1 tools) | `--pure` mode (L0 primitives + self-coding) |
|---|---|---|
| Exposed surface | Over 20 high-level semantic tools (`walk_to`, `interact`, `cross_portal`, `fight`, `equip`, `buy`, `use_item`, `map`, `guide`) | Protocol and self-coding primitives (`protocol_send`, `protocol_observe`, `run_code`, `module_reload`) plus L0-only modules |
| State visibility | White-box inspection of engine memory (`worldService`, script opcodes `0x001B`–`0x0022`, internal wait stack) and direct cursor/facing mutation | Black-box reconstruction: `pal.world` is built exclusively from incremental `SMSG_*` server packets |
| Navigation recovery | `walk_to` aborts and returns control to the LLM whenever a battle or dialogue interrupts movement | Agents write closed-loop state machines in `run_code` (e.g., `global.goTo`) that fight encounters, drain dialogues, clear blockers, and resume pathfinding |
| Combat and menus | `grindTurn` supports only `<45%` healing, AoE spells, and normal attacks; forbids `Qian Kun Yi Zhi`, throws, `Yingu`, `Jiushen`, and protective buffs | Agents author multi-actor tactical engines and pure key/choice menu state machines (`CMSG_KEY` + `CMSG_CHOICE`) in persistent `global` scope |

Under `--pure` mode, all game progression must pass through L0 client messages (`CMSG_MOVE`, `CMSG_INTERACT`, `CMSG_DIALOG_ADVANCE`, `CMSG_CHOICE`, `CMSG_BATTLE_ACTION`, `CMSG_MENU_USE_ITEM`, `CMSG_KEY`, `CMSG_WAIT`, `CMSG_SAVE`, `CMSG_LOAD`). The session code runner (`src/code-runner.mjs`) provides a persistent `global` object across `run_code` calls, packet listeners (`pal.on`/`pal.off`), dynamic MCP tool registration (`pal.registerTool`), and deadline cancellation guards (`RunCodeAbortedError`).

## 4. Metrics and Proposed Experimental Protocol

The implemented primary score is task success averaged across recorded seeds and then equally across tasks with results. `complete` indicates whether planned episodes are present; incomplete runs must not enter a formal ranking. For runs consisting entirely of Baiyue battle-scored tasks, ties in success are broken by **mean battle rounds among wins**, lower first. Ordinary runs instead use mean monetary cost among successes; mixed scoring has no meaningful common efficiency tie-break. Tool calls are not combat rounds. No-success efficiency statistics are undefined, not zero.

Diagnostic metrics include milestone progress, median calls to success, invalid-call rate, virtual time, tokens, and recorded cost. Invalid rate is total invalid calls divided by total tool calls, not an average of episode percentages. Expected movement/interaction interruptions caused by battle or dialogue are soft stops and are excluded from invalid calls. Failure progress counts achieved milestones divided by one plus the number of milestones; success sets it to one. Neither progress nor reference-relative call efficiency is an independent capability score. Zero recorded local/cloud cost can mean unpriced usage, not zero computation cost.

The following is a **proposed** study, not a claim of completed preregistration or experiments:

| ID | Matched comparison | Readout and required control |
|---|---|---|
| E1 | Capability-matched model groups in B-standard | Task/family success differences and 95% intervals; common loop, prompt, context, seeds, and budgets |
| E2 | Same model and task in B versus C | Success change and tool use; fingerprinted guide and atlas; only tasks supporting both |
| E3 | Closed-book quiz versus interactive execution | Knowledge–execution gap; quiz before trace exposure, no external retrieval |
| E4 | Chinese, checked translated, and name-masked conditions | Paired outcomes; translate the stated information surface, preserve goals, distinguish brief-only from full language control |
| E5 | Same-goal starts and short/long chains | Milestones and distance/budget sensitivity; analyze related tasks as families |
| E6 | Audited natural-save chains and synthetic battle variants | Win rate first, winning rounds second for Baiyue; remaining resources and down events as diagnostics |
| E7 | Unseen variants and seeds unused in development | Generalization and replay agreement; no test-trace tuning |
| E8 | Same model and task in `assist` (L1) versus `--pure` (L0 + self-coding) | Success rate, underlying L0 command count, invalid-packet rate, and self-coded tool reuse; matched seeds, virtual time, and wall limits |

Freeze executable/build, assets, saves, tasks/references, goals, prompt, observation/context policy, model identity, decoding/reasoning settings, information sources, call/token/virtual-time/wall limits, and exclusions. Planned formal comparisons use at least three game seeds and three independent decoding samples per condition; this is a minimum grid, not a power guarantee. A fixed game seed does not fix cloud sampling. Publish per-episode outcomes, paired task/family differences, and uncertainty clustered by related task family. Many more independent families are needed for reliable group-level inference. Externally scaffolded agents remain separate; developer origin cannot identify a cultural effect.

Every included task–seed pair must pass reference replay on the frozen build. Every recorded episode must be checked, but a matching replay alone does not convert a provider/harness failure into a valid model failure. Prespecify handling of infrastructure faults, stopping causes, and missing episodes. Public references and development traces create contamination risks; a private test split and independent audit remain future work.

## 5. Development Audits and Exploratory Results

### 5.1 Main working-tree reference audit

On 16 October 2026, the reviewed 23-task working tree passed schema validation and no-engine tests. Full `check --jobs 2` reached the goal on **59/67 reference trajectories**. Five Baiyue failures requested Qian Kun Yi Zhi from a member without that spell at the observed command window: fragile-stocked seed 42, mana-budget seed 43, origin seed 43, and sustain-no-wine seeds 42/43. Three tower references missed the target: tower-chain seeds 43/44 and tower-gate seed 43. These are reference failures, not model scores; their root causes and repairs remain open. Historical Baiyue reference successes on older builds do not override this current-build result. The one-seed palace reserve reference passed, but remains a development pilot.

### 5.2 Local-model pipeline pilot and historical evidence

Qwen2.5-3B (`ollama:qwen2.5-bench-32k:3b`), built-in B-standard, ran the reference-passing handkerchief task on seeds 42/43/44, prompt version 3, code label `3e316b4c-dirty`, and a 120-second wall limit. It completed **0/3**, made partial progress on two seeds, and ended `agent-stopped` on all three after repeated text-only turns. Calls/invalid calls were 8/3, 4/3, and 6/3. All three trajectories passed replay. Its five-question closed-book quiz scored **0/5**. This validates two measurement paths on one model/task; it does not identify whether knowledge or tool use caused failure.

A Qwen2.5-14B seed-42 attempt was killed at a 180-second wall limit and labeled `harness-crash (exit null)`. A partial seed-43 trace also exists after the interrupted scheduling attempt; there is no complete result for it, and seed 44 has no completed result. The attempted run is excluded from model denominators. The fallback's zero calls are not a measurement of the actual partial trajectory. The timeout label requires repair before formal evaluation.

Older repository notes report external Claude Sonnet 9/9 versus local Qwen 0/9 on a three-task pilot, B 0/3 versus C 1/3 on a first-meeting pilot, and 2/3 on a one-life island variant. These are historical, differently versioned records, not additional results in the present denominator or causal ablations. The reported GPT-6 Astra playthrough with roughly 22 hours of footage allowed walkthrough use, rollback, and human strategy discussion; it is development context rather than an independently scored benchmark episode. Model identity and the modifier-free claim require an archived playthrough manifest before use as research evidence.

### 5.3 Medicine and monkey observation/goal audit

The two audited tasks are `classic10-baihe-medicine` and `classic31-banana-monkeys`. The original B observation reduced some plants and animals to generic navigation labels, omitting cues visible in the rendered game. The audit first forwarded `observe(full=true)` correctly so expanded inventory/state could be requested, and corrected item feedback that suggested interaction while dialogue was still open. The monkey goal previously accepted an opening banana-offering line before passage was actually clear. The revised goal requires event object 3482 in scene 192 to reach state 0; the reference now takes 23 calls rather than the prematurely accepted 22.

A subsequent appearance repair shares a reviewed catalog between local `observe` and scene-wide `map`. It matches MGO sprite bytes by SHA-256 and MAP/GOP background pairs by their hashes. Coverage is **64 sprite resources and nine map/background pairs** from both reference routes, including non-goal objects. Captions describe broad leaves and hanging yellow curved fruit, a small tree with reddish-orange round fruit, a water bank, a brown antlered deer, and a circular toothed metal object. They do not name a quest purpose, required offering, reward, or action order. Briefs were unchanged. This supplies visible evidence without explicitly stating the solution.

The catalog is a manually reviewed static/first-frame abstraction, not a runtime vision model or all-game coverage. Unknown or replaced content falls back to neutral descriptions; the lookup assumes immutable assets within a process. Background landmarks matter because some interactive locations have no individual sprite. Scene-wide `map` can expose cues beyond the local observation; availability there does not prove every agent queried or used them. Unreviewed routes and dynamic states remain limitations.

These repairs live in a separate audit worktree based at `3e316b4c`; they are not installed in the main working tree described in Section 5.1. Real-agent comparisons used frozen copies of the previous controlled runtime, adding appearance rendering without changing its engine build. Separate native/source-build checks guard the implementation. A detached copy has a null Git label; explicit source/build/asset/save/task manifests, not the base commit alone, identify the experiment.

### 5.4 Budget calibration and protocol deviations

Fable via the same external CLI used game seeds 43/44 for action-budget calibration. At the original medicine cap of 120, seed 43 exhausted the budget and seed 44 succeeded in 111 calls. Two fresh medicine episodes at a 240-call cap succeeded in **146 and 125 calls**, with 11 and three invalid calls. Monkey calibration succeeded in **48 and 46 calls**, both with zero invalid calls, under an 80-call cap. Thus six calibration episodes comprise five successes and one failure, all replay-verified; they are not six independent successes or an unbiased success estimate.

The predeclared call rule retained a budget if repeated success left at least 25% spare calls; otherwise it selected a round ceiling at least 1.5 times observed successful exploration calls. Medicine was set to **240 calls**, at least 1.5 times 146, and monkey remained **80 calls**, with 40% spare relative to 48. Virtual-time limits remained 3,600 and 1,800 seconds. These small, single-agent calibration samples justify provisional budgets, not a guarantee for every model.

The initial medicine token reserve was 2,880,000. During seed-42 evaluation, Nemotron stopped at 216 calls on that token cap. This episode is retained as an **excluded token-budget diagnostic**, not a completed 240-call failure. A measured built-in turn peak of 20,533 tokens motivated a 32,000-token-per-allowed-call safety reserve: medicine v4 uses **7,680,000 tokens**, with calls/time unchanged. This correction occurred after observing evaluation data; seed 42 is held out for the action-cap decision, not a pristine untouched test set for the full protocol.

One fresh Nemotron medicine episode was then run. The other three medicine episodes had already reached 240 calls under v3. Deterministic v3/v4 checks found identical initial observation, tool responses, and game outcomes for those fixed trajectories; the original model usage and task-version records remain intact. These checks are retrospective policy-invariance diagnostics, **not new model samples or evidence of equivalent external token enforcement**. Monkey v3 retains 960,000 tokens for built-in agents. CLI token caps are not incrementally enforced: Fable reported 12,055,420 medicine tokens and 2,866,716 monkey tokens, including cached input. The experiment is matched on game action limits, not equal token use or compute.

### 5.6 Failure evidence and interpretation

Gemma's medicine run interacted with the doctor 112 times and advanced dialogue 117 times without acquiring an ingredient. Its monkey run repeated one off-route movement target 22 times. Thus zero or few invalid calls can coexist with no task progress. GPT-OSS repeatedly queried the doctor and attempted actions incompatible with dialogue/menu mode; its monkey episode tried items on indoor characters and acquired no banana or maze milestone. Nemotron's replacement medicine episode made 56 invalid calls and repeatedly queried the doctor (65 calls) or advanced dialogue; its monkey episode detoured through scenes 179, 202, and 214 without reaching the target maze. These traces support diagnoses of repetition, mode tracking, and failed exploration rather than resource exhaustion alone.

Fable medicine acquired ginkgo at call 11 and carp at 27, but no antler by 240. It made 117 movement calls, 35 map calls, 25 waits, and six loads, repeated fishing after reloads, and never interacted with the ground trap or used a trap item. The scene's trap was pre-existing; the trace does not show the agent placing it incorrectly, nor establish that pickup/reposition is mandatory. The observed problem is persistence with ineffective pursuit and poor reuse of acquired progress. In the monkey episode, map call 3 supplied the broad-leaf/yellow-fruit description and the agent entered the maze at call 20, but later returned to the start and queried villagers instead of collecting the fruit. Calibration episodes did collect it. This is consistent with unstable clue retention and resource preparation; it does not by itself prove an internal reasoning or memory mechanism.

Native tests establish selected observation contracts and reference solvability, not universal environment correctness. The built-in six-result context policy, CLI differences, manual caption coverage, game prior knowledge, exploration, and action planning all remain intertwined. These tasks measure an agent system under a specified information interface; they are not single-factor resource-planning tests.

### 5.7 Three-agent end-to-end validation of `--pure` mode via self-coding playthroughs

On 19–20 October 2026, on the `--pure` runtime introduced at commit `1a13a6ef`, we conducted three independent end-to-end protocol completeness and self-coding validations of `--pure` mode under identical deterministic lockstep (`--pure --seed 1`) using **Argon**, **GPT-6.1-Sol** (`gpt-6.1-sol`, `reasoning_effort="medium"`, Codex CLI `0.162.0-alpha.17.2`), and **Claude Opus 5.5** (`claude-opus-5-5`, CLI `2.1.294`). The three playthroughs illustrate a clear spectrum of self-coding paradigms and compute/efficiency trade-offs under identical L0 constraints:

1. **Compact tactical state machine and low-level precision (Argon, 731 lines)**: Concentrates 70% of its library into a single 478-line coordinated combat state machine (`global.fightBattle`), avoiding heavy grinding and instead exploiting `Yingu` stealth windows, `Zhenyuan Huti` damage halving, `Wind Spirit Orb` (`+50%` wind resistance) itemization, and per-round action deduplication to defeat `Baiyue` at `Lv42/35/40` in 11 rounds with zero party deaths.
2. **Ultra-compact functional graph routing and single-session throughput (GPT-6.1-Sol, 135 lines, 845 calls in 1 session)**: Independently discovers connected-component flood-fill and bytecode portal compilation (`global.flood`, `dungeonRoute`, `positionRoute`), but expresses its entire evolving runtime as dense functional one-liners (`167.0K` total output tokens—one-eighth of Argon and one-third of Opus 5.5), clearing all 36 `Kuilei Bugs` in the Trial Cave in 9 minutes and completing the game in a single uninterrupted 2.46-hour session at `Lv45/40/44`.
3. **Comprehensive bytecode graph compiler and economic scaling (Claude Opus 5.5, 1,427 lines)**: Formulates world traversal and resource collection as general graph-compilation problems over raw script bytecode (`path2`, `compsOf`, `regionGraph`, `farmTour`—subsequently extracted into the standalone module `src/bytecode-compiler.mjs`), systematically clearing all 36 `Kuilei Bugs` in the multi-floor Trial Cave (`Scenes 217–219`) to accumulate `$118,565` and `Lv53/49/51`, then combining `Jingang Zhou` / `Zhenyuan Huti` mitigation with 12+ `Qian Kun Yi Zhi` throws (`$64,006` spent) and a `Jiushen` finisher.

Together, these three full playthroughs demonstrate that the `--pure` L0 packet protocol and `SMSG_*` state stream support diverse agent-synthesized architectures from new game to final credits, and that both closed-loop tactical state machines and bytecode-compiled graph planners surpass the static built-in L1 heuristics on multi-floor mazes and multi-phase bosses. Their evidential status must nevertheless be kept distinct: all three playthroughs are **interactive engineering and upper-bound validations** that permitted checkpoint reloads, cross-segment code refinement, and static data-table inspection (`pal.readData`), not zero-rollback single-episode benchmark scores under fixed call budgets. They therefore do not enter the controlled evaluation denominator of Section 5.5.

## 6. Discussion and Limitations

**Construct and information validity.** Correct tool syntax, available clues, retained clues, recalled game knowledge, tool self-coding, and successful planning are different observations. Missing visual semantics and premature goal detection were environment defects. Repairs improve the measurement contract; they do not warrant attributing every later failure to the model. A stronger study needs observation/context ablations and independent failure annotation. While `--pure` mode removes white-box L1 pre-checks and static heuristic limits, it couples code synthesis and debugging skill with domain planning, requiring the paired E8 protocol for separation.

**Sampling and adaptation.** Calibration uses one external agent and two seeds. Evaluation uses one sample per task/model on a seed already used in earlier development comparisons; the token correction further uses evaluation feedback. Two selected difficult tasks and correlated seeds cannot estimate overall RPG competence. No cultural or regional effect is identified. Synthetic saves and modified classic-save levels/cash also limit natural-play interpretations.

**Scaffolding and budgets.** CLI and built-in agents differ in context retention, token enforcement, and usage reporting. Equal call limits do not imply equal compute. Under `--pure` mode, a single `run_code` invocation can dispatch dozens of underlying `CMSG_*` commands inside the sandbox; comparisons against `assist` mode must therefore report both top-level MCP tool calls and underlying L0 command counts (`commandsSent`). Costs for cloud/local adapters are not consistently priced. Failed runs have no winning-round or success-efficiency statistic. Wall-time classification and eight current reference failures remain release blockers.

**Reproduction and release.** A replay establishes action/outcome consistency in its recorded environment, not reproducibility of cloud generation or validity across engine updates. General tasks need explicit manifests beyond Git labels. The accompanying evidence index contains extracted numbers, provenance, and hashes; full traces and frozen runtimes currently reside in local ignored directories and have not been publicly archived. Proprietary assets and music are not proposed for redistribution; asset rights and release permissions need review. Public references increase contamination risk, and a hidden test set is not yet implemented.

## 7. Conclusion

Agent-PAL-Bench provides a working protocol and task collection for text-mediated decisions in a Chinese RPG, supporting both a built-in high-level semantic tool layer (`assist` L1) and a low-level protocol plus dynamic self-coding layer (`--pure` L0). The current evidence supports partial reference feasibility, a local end-to-end pilot, a documented two-task observation/goal audit, and a three-agent end-to-end `--pure` completeness validation in which Argon, GPT-6.1-Sol, and Claude Opus 5.5 independently synthesized 731-line, 135-line, and 1,427-line runtime libraries to complete the entire game from new game to final credits (`Slots 1–99`). In controlled single-episode benchmark trials, after repairs and provisional action-budget calibration, the seed-42 two-task evaluation still records 0/8 successes, alongside replay consistency and concrete failure traces. A frozen release, repaired references, controlled scaffolding, independent samples, and a held-out evaluation are needed before comparative capability, tool-layer, or cultural-knowledge conclusions.
