# Agent-PAL-Bench：以经典中文角色扮演游戏评测文本智能体的长程决策能力

> 论文草稿 v0.4，证据审查日期：2026-10-21。本文区分已实现机制、开发审计、探索性 agent 实跑和拟开展实验，尚不是冻结发布的评测或能力匹配的模型排行榜。中英文稿采用相同的结论与结果；英文 Markdown 是独立英文 LaTeX 稿的内容来源。

## 摘要

持续状态的角色扮演游戏结合了对白理解、空间探索、跨场景因果与资源管理。本文提出 Agent-PAL-Bench，在《仙剑奇侠传》的无头运行环境中，通过结构化工具和文本状态反馈评测智能体，游戏录像不作为模型输入。除默认暴露高级语义工具的 `assist`（L1）层外，环境还实现了仅暴露底层协议原语（L0）与会话内动态自编程（`run_code` / `module_reload`）的 `--pure` 模式。审查时的工作题库包含 23 题、67 个预设任务—种子局次，每题规定起点、状态目标、预算、资料条件与参考轨迹。当前构建的参考解审计有 59/67 局达到目标，其余属于发布前必须处理的参考解问题，不是模型失败。另一套冻结的两题审计修复了外观线索遗漏和提前计胜，校准动作预算，再让三个内置云端 agent 和一个外部脚手架 agent 在游戏 seed 42 上实跑；八局均耗尽调用预算、未成功，并通过轨迹重放。校准成功和参考解成功另行报告。此外，我们在确定性锁步（`--seed 1`）下使用三个外部智能体（Argon、GPT-6.1-Sol 与 Claude Opus 5.5）独立完成了 `--pure` 模式的端到端验证：三个智能体仅凭 `SMSG_*` 状态包与 `CMSG_*` 原语，在会话内分别自编写出 731 行、135 行与 1,427 行运行时库（涵盖通用字节码图寻路、连通分量迷宫规划、抗性自适应战斗引擎与菜单状态机），各自从“新的故事”打穿全部 11 章并击败最终 BOSS 拜月教主（存档槽位 `Slots 1–99`）。进一步地，我们围绕四道代表性关卡——**大理祈雨祭坛（`classic48-rain-orbs`）**、**白河村三味药材（`classic10-baihe-medicine`）**、**拜月教主决战（`baiyue-single-origin`）**与**扬州女飞贼及紫金葫芦长链（`classic19-yangzhou-gourd`）**——配合 22 题闭卷先验测验（`bench quiz`）、跨种子复现、预算扩容与“禁绝酒神·乾坤一掷·隐蛊”反事实消融实验，对横跨 10–12 款前沿与开源云端模型的认知行为进行了切片剖析，系统揭示了：（1）45° 斜向等距网格下的手性对称二义性如何诱发推理模型的十万字内省死循环，以及单步认知探针（Epistemic Probe）与单轮输出上限熔断器的破局机制；（2）先验攻略污染与真正零样本开荒在多阶段探索中的分离，以及单一步数阈值造成的“截断错觉”；（3）先验知识的双层剪枝效应（表层速通套路 vs 底层机制常识）、上下文强化学习中的“近因过拟合遗忘”，以及回合制批量结算（`PerformAction`）下的单招伤害线性消元法与时序归因谬误；（4）长程跨场景侦探链中局部错误先验（如 `gourd#q4` 井边误记）引发的确认偏误与纠偏速度分野（22 步 vs 82 步）、战后掉落物遗落的自省回溯，以及零先验智能体逆向复用前期追贼建立的跨场景屋顶空间图（Episodic Spatial Graph Reuse）。这些结果揭示了观察保真度、上下文保留、先验污染、内省停止准则、工具抽象层级与自编程架构分化对测量的影响，尚不能证明模型国别优势、修复带来的因果成功率提升，或对纯规划能力的单因素测量。

**关键词：**语言智能体；游戏评测；中文角色扮演游戏；长程规划；文本交互；工具自编程；认知探针；可复现性

## 1. 引言

知道水灵珠在哪里，不等于能找到人物、保留信物、跨场景并在预算内完成交换。知道决战需要输出，也不等于能在前置战斗中保留资源，或在治疗者封咒、倒地时调整行动。持续状态的游戏让我们观察智能体如何把信息转化为有后果的动作。

选择中文仙侠 RPG，是因为对白、人物关系、隐含前置、地图机关、装备和消耗品在同一人工创作的世界中相互作用。中文游戏语言与文化熟悉度能否改善现场决策，是开放的研究问题。模型开发者所在地不能代表这种熟悉度；归因前必须控制规模、预训练、推理预算、工具、资料权限和 agent 脚手架。

本文贡献包括：（1）从连续 RPG 制作可回放任务，包含同目标起点变体、道具因果链与合成战斗配置；（2）以固定存档、游戏种子、虚拟时间、状态谓词与动作重放定义协议；（3）明确工具与提示条件，并区分内置白盒高级工具层（`assist` L1）与纯协议自编程层（`--pure` L0 + `run_code`/`module_reload`）；（4）通过两题开发审计展示观察遗漏、提前计胜与上下文策略如何干扰失败归因，并通过 `--pure` 模式从新游戏到全剧终的端到端自编程通关验证 L0 协议的完备性；（5）通过空间几何解谜（`classic48-rain-orbs`）、跨场景采药（`classic10-baihe-medicine`）、终局 Boss 战（`baiyue-single-origin`）与长程侦探机关链（`classic19-yangzhou-gourd`）四项专题行为学实验，结合闭卷先验测试与反事实消融，定量剖析推理模型的内省死循环、零样本探索代价、局部错误先验纠偏、跨场景空间图复用、败后复盘演化及回合制批量结算下的因果归因机制。已实现环境、开发验证、行为切片实验与拟开展的全题库推断性实验具有不同证据地位。

## 2. 相关工作

[AgentBench](https://arxiv.org/abs/2308.03688)覆盖多种交互环境；[TextWorld](https://arxiv.org/abs/1806.11532)提供状态追踪和可控文本游戏生成，本工作使用已有人工创作的 RPG。[Jericho](https://arxiv.org/abs/1909.05398)研究人工创作的交互小说，本环境同样要求探索，并加入队伍、装备、消耗品与回合制战斗。[ScienceWorld](https://arxiv.org/abs/2203.07540)区分知识回忆和在环境中应用知识；[ALFWorld](https://arxiv.org/abs/2010.03768)连接文本与具身环境，提示我们不能将文本决策等同于视觉理解。[GameBench](https://arxiv.org/abs/2406.06613)与[BALROG](https://arxiv.org/abs/2411.13543)提供更广的游戏评测参照。

RPG 智能体并非新的研究对象：[PokeAgent Challenge](https://arxiv.org/abs/2603.15563)已有对战和 RPG 速通赛道，[PokeGym](https://arxiv.org/abs/2604.08340)研究视觉长程任务与适应。本工作的定位是中文人工剧情 RPG、可检查的目标谓词与结构化文本交互，不主张首次评测 RPG 规划、持续世界或游戏 agent，也不直接比较不同视觉接口或脚手架的成绩。

## 3. 环境与任务

### 3.1 交互与重放

每局在独立游戏进程中从新游戏、经典 RPG 存档或固定评测槽位开始，设置游戏随机种子。工具包括 `observe`、`map`、移动、交互、推进对白、菜单、物品、法术和战斗动作。调用之间游戏暂停，推进型动作增加虚拟时间，观察与查资料不推进游戏；模型推理延迟本身不会让游戏继续运行。墙钟上限仍是独立约束。各局存档与地图记忆隔离。录像用于人工复核，不送给 B/C 档模型或判分器；审查题库未开放视觉 A 档题。

题目定义起点、目标、可选里程碑与失败条件、预算和工具。判分器读取场景访问、背包、事件对象、战斗结果及对白历史等状态。`check` 重放参考解；`verify` 重放记录的动作，对照逐步判分快照与游戏终局。它不重新调用模型，也不独立验证 token 计量、成本或模型侧终止原因。普通重放通过不能证明观察文本完整准确；本次外观审计另外增加了原生观察契约与特定工具反馈一致性检查。参考解只证明该版本和种子的一条可行轨迹，不是最优策略或模型成绩。

普通题的 runner 记录 Git 版本标签、任务版本、种子、提示版本和日志；战斗计分题另记录运行时/资产及题目/存档指纹。普通题尚未自动获得全部这些哈希，因此本次冻结外观实验另存清单。仅有 `-dirty` 标签不能标识准确的可执行代码、素材和题目内容。

### 3.2 审查时的工作题库

以 `3e316b4c` 为基底、包含未提交开发题的主工作树有 **23 题、67 个预设任务—种子局次**：23 题支持 B，18 题同时支持 C；经典存档起点 11 题、固定评测存档 8 题、新游戏 4 题。这是开发目录数量，不是已全部验证的发布集，也不是 67 个独立故事样本。

| 能力类别 | 代表任务 | 判据示例 |
|---|---|---|
| 剧情推进 | 端菜、扬州夜事 | 指定剧情或对白发生 |
| 空间机关 | 仙灵岛石像、锁妖塔铜门 | 场景或事件状态改变 |
| 跨场景道具链 | 手绢换水灵珠、五灵珠祈雨 | 取得物品或完成因果目标 |
| 生存与战术 | 仙灵岛一条命、拜月变体 | 胜利且符合题目约束 |
| 资源配置 | 王宫前置战资源保留试题 | 剧情/战斗谓词及剩余物品、现金达标 |

新游戏、登岛和走廊三个起点采用相同的初见灵儿目标及普通失败规则，但起点与预算不同，不能视为等预算下只改变规划长度的实验。一条命变体增加约束，应另列条件。王宫资源试题仅有 seed 42，参考解 35 次调用，尚未形成连续的“侍卫—树妖—拜月”评测。四道拜月单战题改变物资或角色能力，属于合成配置，不能用来估计自然练级的效果。

### 3.3 资料、提示和上下文条件

B 档提供结构化文本工具，C 档另外开放攻略和全图。提示条件独立设置：`standard` 隐去一部分 `full` 会揭示的脚本用途和前置要求。Standard 并不保证与像素画面信息等价：坐标、ID、导航分类和状态摘要仍是抽象信息，标准档也可能包含物品效果。`observe(full=true)` 是展开观察，与环境设置 `hints=full` 不是一回事。

内置循环仅保留最近 **6 条工具结果全文**，较早结果替换为占位文字，模型自己的文字和调用记录仍保留。旧线索可能消失，除非 agent 记下或重新获取。Claude CLI 自行管理上下文。内置循环每轮累计用量并执行 token 限额，外部 CLI 在局末才合并用量，不能逐轮执行题目 token 上限。这些差异要求分开报告。只翻译任务 brief 仍保留中文游戏对白；全英文观察与完整名称遮蔽尚未实现。

### 3.4 辅助层（L1）与纯粹层（--pure L0 + 动态自编程）

为分离“预置高级工具脚手架的辅助作用”与“智能体基于原始协议自我构建策略与工具的能力”，运行环境实现了两套严格分层的工具面：默认的 `assist`（L1）模式与 `--pure`（L0 + 动态自编程）模式。

| 维度 | `assist` 默认层（内置 L1 工具） | `--pure` 纯粹层（L0 原语 + 会话自编程） |
|---|---|---|
| 暴露接口 | 20 余个高级语义工具（`walk_to`、`interact`、`cross_portal`、`fight`、`equip`、`buy`、`use_item`、`map`、`guide` 等） | 协议收发与自编程接口（`protocol_send`、`protocol_observe`、`run_code`、`module_reload`）及基于纯 L0 的外部模块 |
| 状态可见性 | 白盒读取引擎内存（`worldService`、脚本指令表 `0x001B`–`0x0022`、内部等待栈），直接修改朝向与菜单光标 | 黑盒协议重建：仅靠订阅 `SMSG_*` 增量包在 `pal.world` 中拼出场景、坐标、背包、对白与战况 |
| 寻路与中断恢复 | `walk_to` 遇敌或触发对白即中断返回，需模型在下一轮手动接管 | 智能体可在 `run_code` 中自写闭环状态机（如 `global.goTo`），遇暗雷或对白自动接管并在战后继续寻路 |
| 战斗与菜单自动化 | `grindTurn` 仅支持 `<45%` 回血、群攻与普攻，禁用乾坤一掷、投掷、隐蛊、酒神与护体增益 | 智能体在持久 `global` 作用域自写协同战斗引擎与纯按键/选项菜单状态机（`CMSG_KEY` + `CMSG_CHOICE`） |

在 `--pure` 模式下，所有游戏推进均须经由 L0 客户端消息（`CMSG_MOVE`、`CMSG_INTERACT`、`CMSG_DIALOG_ADVANCE`、`CMSG_CHOICE`、`CMSG_BATTLE_ACTION`、`CMSG_MENU_USE_ITEM`、`CMSG_KEY`、`CMSG_WAIT`、`CMSG_SAVE`、`CMSG_LOAD`），会话代码运行器（`src/code-runner.mjs`）提供跨调用持久化的 `global` 对象、`pal.on`/`pal.off` 事件监听、动态工具注册（`pal.registerTool`）及超时中断保护（`RunCodeAbortedError`）。

## 4. 指标与拟议实验协议

已实现主分数先对每题有记录的种子计算成功率，再对有结果的题等权平均；`complete` 表明预设局次是否齐全，未完成运行不能进入正式排行。全部采用拜月战斗计分题的运行，先比较成功率，同分再比较**成功局平均战斗回合数**，越少越好。普通题同分比较成功局平均金钱成本，混合计分没有可解释的统一效率次序。工具调用数不等于战斗回合数；没有成功局时，胜局效率应为空，不能记为零。

诊断指标包括里程碑进度、成功调用中位数、无效调用率、虚拟时间、token 和已记录成本。无效率为总无效数除以总调用数，不是各局百分比的平均。移动/交互因遇敌或对白而正常提前停下属于 soft stop，不计无效。失败进度为已完成里程碑数除以“里程碑总数加一”，成功则为一。进度与相对参考解的调用效率均不是独立能力分数。本地或云端记录成本为零可能只是没有定价，不能解释成计算成本为零。

下表是**拟开展**的研究，尚未完成预注册或全套实验：

| 编号 | 配对比较 | 读数与必要控制 |
|---|---|---|
| E1 | 能力匹配的模型组，B-standard | 任务/任务族成功率差与 95% 区间；统一循环、提示、上下文、种子和预算 |
| E2 | 同一模型同题 B 与 C | 成功变化与调用；冻结攻略/全图，仅用同时支持两档的题 |
| E3 | 闭卷知识测验与现场执行 | 知识—行动差距；先测验、不接触轨迹、不检索 |
| E4 | 中文、核校译文与名称遮蔽 | 配对结果；明确翻译的信息范围，保留目标语义，区分仅 brief 翻译与完整语言控制 |
| E5 | 同目标起点与短/长链 | 里程碑、距离及预算敏感度；相关题按任务族分析 |
| E6 | 审计自然存档链与合成单战 | 拜月成功率优先、胜局回合其次；剩余资源及倒地为诊断 |
| E7 | 开发时未见的变体与种子 | 泛化及重放一致性；不按测试轨迹调参 |
| E8 | 同一模型同题 `assist`（L1）与 `--pure`（L0 + 自编程） | 成功率、底层 L0 指令数、无效包率与自写工具复用率；对齐种子、虚拟时间与墙钟上限 |

正式实验需冻结可执行构建、素材、存档、题目/参考解、目标、提示、观察/上下文策略、模型身份、采样/推理设置、资料、调用/token/虚拟时间/墙钟限额及剔除规则。计划每条件至少三个游戏种子和三次独立解码采样，这只是最小测量网格，不是统计功效保证。游戏种子固定不等于云端采样固定。应公开逐局结果、配对任务/任务族差异与按相关任务族聚类的不确定性；可靠的模型组推断还需要更多独立任务族。外部脚手架单列，开发者国别不能识别文化效应。

计入的每个题目—种子必须在冻结构建通过参考解；每局需核验，但重放一致不能把 provider/harness 故障转换成有效模型失败。需事先定义基础设施故障、终止原因和缺失局处理。公开参考解及开发轨迹会带来污染风险，私有测试集与独立审计仍待建设。

## 5. 开发审计与探索结果

### 5.1 主工作树参考解审计

3. **单一步数阈值造成的“截断错觉（Truncation Illusion）”**：若仅汇报 `120` 步截断下的二元成功率（`0%`），零先验但最终以 143/176 步 100% 通关的 `Claude Opus 5.5` 会与放宽至 240 步仍停留在 `0.00–0.25` 进度的 7 款中小模型混为一谈。多档预算或生存曲线分析对于区分“零样本完备探索超支”与“能力缺失型卡死”至关重要。

这场反事实禁招消融实验揭示了智能体先验结构与科学归纳法的两项深层规律：
1. **先验知识的“双层结构（Two-Layer Prior Structure）”与“牛顿式”科学归纳的殊途同归**：即便剥夺了第一层“表层速通套路先验（Walkthrough Meta Priors）”，`GPT-6.1-Sol` 与 `Gemini 4 Argon` 仍保有第二层**“底层机制常识先验（Domain Mechanics Priors）”**——它们先天知道终局 BOSS 免疫即死与定身控制、且高伤持久战必须优先叠护体减伤，因而仅用 **2 命（176 步 / 114 步）** 即直达 37–39 回合胜局。相反，零先验的 `Claude Opus 5.5` 付出了 **前 8 命（296 步）的实验学费**逐一证伪双毒即死配方（`三尸蠱+血海棠`、`孔雀膽+鶴頂紅`）与 `捆仙繩` 麻痹，在第 9–10 命独立发现护体减半与 8 回合过期定律，最终在 **第 11 命（542 步）** 算准 `<5%`（`1,638 HP`）斩杀线用 `化屍水` 秒杀 `1,502 HP` 的拜月，以全场最快的 **36.00 回合** 反超夺冠。先验赋予极致的样本效率（2 命通关），而科学归纳赋予无惧未知规则的终极上限。
2. **回合制延迟批量结算下的时序归因陷阱与控制变量线性消元法（`ΔHP_round = x1 + x2 + x3`）**：为何同样悟出“开局三盾 + 定期续杯”的 `DeepSeek V4.1 Flash` 打满 700 步（23 命）仍止步于 `21,022 HP`？根源在于《仙剑 95》战斗引擎分为指令收集期（`SelectAction`）与批量执行期（`PerformAction`）：1 号位李逍遥（第 `t` 步）与 2 号位赵灵儿（第 `t+1` 步）提交指令时回合尚未结算，面板血量差分恒为 `0`；直到 3 号位阿奴（第 `t+2` 步）提交指令后，引擎才一次性结算三人总伤害 `ΔHP_round = x1 + x2 + x3`。`DeepSeek V4.1 Flash` 误将延迟批量反馈当作单步即时反馈，看到 1、2 号位行动后 Boss 血量未变，便在思考日志（`Turn @696, @699`）中断定**“拜月对李逍遥、赵灵儿的伤害法术完全免疫（天剑、剑神、武神、冰蚕蛊均为 0 伤害），只有 3 号位阿奴的火神/蛊术有效”**，从而主动废弃了全队三分之二的火力，甚至在同一回合对同一倒地队友连喂 3 颗复活药（`#477–#479`）。与之相反，`Claude Opus 5.5` 在第 3 命（`#58–#84`）明确设计了**控制变量线性消元实验**——利用已知固定 `1,000` 伤害的 `無影毒` 或 `0` 伤害的加血技能作为定值锚点（`x_unknown + 1000 + 1000 = ΔHP` 或 `x_attack + 0 + 0 = ΔHP`），每回合仅放入 1 个未知技能，短短 3 个回合即精确解出 `劍神 ≈ 510`、`泰山壓頂 ≈ 436`、`萬蟻蝕象 ≈ 472`、`投擲鬼牙刀 ≈ 1,587` 及 `冰蠶蠱 ≈ 230–360` 的独立伤害。

1. **高权限自写 Buggy 寻路器死锁 vs. B 档受限原语的高效破局（`M1: night-alarm`）**：在 `--pure` 全流程模式中，`DeepSeek V4.1 Flash` 虽在第 63 轮即从 `scripts.json` 读出客房入口 `1803 @ (83, 69)` 与开门脚本 `script 22`，却因手写静态网格 BFS 一刀切拉黑了所有 `touch-trigger`（将唯一连接一楼与二楼的 `006E` 跨墙楼梯 `1806 @ (61, 94)` 误作危险传送门封死，又在地图右侧虚空假走廊反复踩进 `(94, 79)` 厨房传送点），在 `Scene 93` 连续空转 **46 轮（约 2,800 次调用）**。相反，在完全剥夺 `run_code` 与底层脚本读取权限的 B 档下，`Gemini 4 Argon`（**第 16 步**）、`GPT-6.1-Sol`（**第 18 步**）与零先验 `Claude Opus 5.5`（第 46 步进店后仅花 **10 步**，`#47–#56`）均依靠 `map()` + `search()` + `interact(1825/1826)` 顺畅开门入住，比高权限但存在语义分类缺陷的自写规划器快了 **170 倍以上**。

## 6. 讨论与局限

**构念与信息有效性。** 合法语法、线索可查、线索保留、知识回忆、工具自编程和规划成功是不同观察。外观遗漏及提前计胜属于环境缺陷，修复改善测量契约，不足以把之后每次失败都归咎于模型；还需观察/上下文消融与独立失败标注。5.8–5.11 节的四项专题实验进一步表明：（1）当环境存在手性对称二义性或先验不可观测状态时，缺乏元认知停止准则的推理模型会陷入十万字量级的纯演绎内省死循环，而轻量级认知探针（Epistemic Probe）或外源性单轮 token 熔断器能以 1 步交互打破僵局；（2）在经典游戏基准中，预训练先验具有“表层攻略记忆”与“底层机制常识”双层结构，且不完整或局部失真的表层记忆（如 `gourd#q4` 误记在井边触发）反而会诱发确认偏误与高达 80 步的搜索停滞，必须配合闭卷测验（`bench quiz`）与反事实机制消融（如 `BENCH_STRIP_CHEESE=1`）才能将“背攻略速通”、“局部错误先验纠偏”与“零样本科学归纳/跨场景空间图复用”解耦；（3）当环境采用回合制延迟批量结算（`ΔHP_round = x1 + x2 + x3`）时，能否先理解观测仪器的时序特性并通过控制变量消元分离单步因果，是区分高阶科学推理与机械差分归因的关键分水岭。`--pure` 模式去除了内置 L1 工具的白盒预检与静态策略限制，但也把编程调试能力与领域规划能力耦合在一起，需要通过 E8 配对实验加以分离。

**采样与适应。** 校准仅一个外部 agent、两个种子。5.5 节探索性评测每模型每题一个样本，seed 42 在更早开发对比已用过，token 修正又使用评测反馈；5.8–5.11 节的跨模型切片与消融实验虽引入了 `seed 43` 对照、预算扩容（`120 → 240 → 320 → 560/700`）与自动读档复盘，但仍聚焦于四道代表性关卡。特选难题及相关种子不能无偏估计整体 RPG 能力，也不能识别文化或国别效应。合成配置、经典存档已有的等级/现金改动同样限制自然游玩解释。

**脚手架与预算。** CLI 和内置循环的上下文、token 执行与用量报告不同，等调用不代表等计算。5.9 节白河村实验证明，单一硬性调用阈值（如 `120` 步）会产生“截断错觉”，将零先验模型的完备房间探索（143–176 步 100% 通关）与彻底卡死混为一谈；5.8 节祈雨坛实验则表明单轮最大输出上限（`4,096` vs `16,384`）本身会改变推理模型的行为轨迹。在 `--pure` 模式下，一次 `run_code` 调用可在沙箱内下发数十条底层 `CMSG_*` 指令，因此与 `assist` 模式对比时必须同时报告顶层 MCP 调用数与底层 L0 指令数（`commandsSent`）。云端/本地成本没有一致定价；失败局没有胜局回合或成功效率。墙钟分类和当前八条参考解失败仍阻碍正式发布。

**复现与发布。** 重放证明记录环境下动作/结果一致，不证明云端生成可重复或新引擎仍成立。普通题需要 Git 标签之外的显式清单。随稿证据索引保存提取数字、来源和哈希，完整轨迹与冻结运行时目前仍在本地忽略目录，未公开归档。本文不拟分发专有素材与音乐，发布权限及资产权利仍需审查。公开参考解有污染风险，隐藏测试集尚未实现。

## 7. 结论

Agent-PAL-Bench 提供中文 RPG 文本决策的工作协议与题集，同时支持内置高级语义工具的 `assist`（L1）模式与仅靠底层协议原语及动态自编程的 `--pure`（L0）模式。现有证据支持部分参考解可行性、本地端到端链路、可追溯的两题观察/目标审计，以及 `--pure` 模式下三个外部智能体（Argon、GPT-6.1-Sol 与 Claude Opus 5.5）分别通过自写 731 行、135 行与 1,427 行运行时库从新游戏打穿至全剧终（`Slots 1–99`）的三模型端到端完备性验证。围绕祈雨祭坛（`classic48-rain-orbs`）、白河村采药（`classic10-baihe-medicine`）、拜月决战（`baiyue-single-origin`）与扬州紫金葫芦长链（`classic19-yangzhou-gourd`）开展的跨模型认知行为学与反事实消融实验进一步证明：交互式智能体的核心瓶颈不仅在于静态推理深度，更在于何时停止空想发出 1 步认知探针、如何在无先验开放世界中平衡完备探索与快速止损、如何在局部错误先验下快速证伪并逆向复用跨场景情景空间记忆、如何在多轮败后复盘中实现单调累积进化而非近因遗忘，以及如何在延迟批量结算的黑盒观测中通过控制变量实验完成准确的因果归因。全面比较模型能力、工具抽象层级或文化知识前，仍需完成全题库冻结发布、参考解修复、脚手架统一控制、多独立采样与真正留出的隐藏评测集。
